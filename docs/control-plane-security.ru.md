# Защита панели AmberGate

В AmberGate v0.2.0 незавершённые запросы имеют отдельный лимит соединений. Авторизованные запросы панели, отчёты агентов и туннели используют отдельные лимиты. Заголовки должны поступить полностью за 10 секунд, JSON-тело — за 30 секунд. Отправка отдельных байтов не продлевает этот срок. Долгие авторизованные SSE и WebSocket-соединения работают по своим правилам.

Порт панели **8083 остаётся HTTP**. Используйте приватную сеть и защищённый HTTPS-прокси для удалённого доступа. Сертификаты доменов приложений не включают HTTPS на отдельном порту панели.

## Клиенты за прокси

На центральном gateway укажите только адреса прокси, которые видны панели как TCP-клиенты:

```dotenv
AMBERGATE_ADMIN_TRUSTED_PROXIES=10.0.0.5/32
AMBERGATE_SECURE_COOKIE=true
AMBERGATE_AGENT_TARGET_LIMIT=128
```

Готовые Compose-файлы репозитория передают эти переменные из `.env`. В существующей установке через first-start добавьте их также в `environment` сервиса gateway в установленном Compose-файле. После изменения пересоздайте gateway:

```bash
docker compose up -d
```

В настройках HTTPS-прокси для панели перезаписывайте адрес клиента:

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
```

Полный пример есть в [инструкции агента](agents.ru.md). При нескольких прокси каждый должен передавать проверенный адрес своего клиента; доверяйте только этим промежуточным узлам. AmberGate разбирает цепочку от ближайшего прокси и останавливается на первом недоверенном адресе. Пустой список отключает доверие к заголовкам. Повторные, некорректные и слишком длинные заголовки приводят к использованию адреса TCP-клиента. Не указывайте `0.0.0.0/0` и сети обычных пользователей.

Для каждого клиента разрешён начальный запас в 10 попыток входа; одна попытка восстанавливается каждые 30 секунд. Ответ `429` содержит `Retry-After`. Число одновременных проверок пароля ограничено отдельно; они не блокируют проверку существующих сессий. Пользователи за одним реальным NAT по-прежнему делят IP-лимит: для независимого доступа используйте приватный административный канал. Доверенные прокси маршрутов приложений настраиваются отдельно.

## Цели агентов

По умолчанию агенту доступно 128 сохранённых целей. На центре это меняется через `AMBERGATE_AGENT_TARGET_LIMIT` в диапазоне 1–512; общий предел — 1024. Отчёты и предпросмотр не создают новые порты. Ручной выбор или применение labels выделяют цели одной операцией; отклонённая операция не занимает квоту.

Уже существующие адреса продолжают работать даже при снижении квоты. При запуске удаляются только выделения без ссылок из черновика, оставшейся истории и ручного выбора. Сохраняйте приватную копию всего `/data`; не удаляйте `agent-ports.json` для сброса квоты. Ошибки квоты видны в состоянии агента или предпросмотре labels. Освобождение сохранённых целей требует осознанного удаления устаревших маршрутов и ссылок на них.
