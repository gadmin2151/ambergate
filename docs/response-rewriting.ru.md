# Сохранение базового пути приложения

[English](response-rewriting.md) · [README](../README.ru.md)

Приложение под `/api5` может вернуть `Location: /login`, cookie с `Path=/` или HTML со ссылками `/public/...`. Без переписывания ответа браузер покидает `/api5` и запрашивает эти адреса от корня домена.

В редакторе маршрута включите **Сохранять базовый путь в ответах**, сохраните и примените конфигурацию. Для запросов включается удаление префикса: приложение получает `/login`, а браузер использует `/api5/login`. Это работает и для прямых серверов, и для целей через агента. Настройки самого приложения не меняются.

AmberGate формирует стандартные правила Nginx:

- Вход `/api5` перенаправляется на `/api5/` с кодом 308, сохранением параметров и HTTP-метода.
- Корневые перенаправления `Location`/`Refresh` получают префикс. Также обрабатываются абсолютные адреса домена маршрута и его upstream. Внешние адреса и пути с уже добавленным префиксом сохраняются.
- Пути cookies ограничиваются `/api5`.
- В HTML переписываются корневые адреса в атрибутах `href`, `src`, `action`, `formaction` и `poster`, заключённых в кавычки, включая `<base href="/">`. Внешние ссылки вида `//cdn.example.com/...` сохраняются.

Раздел **Дополнительные замены в HTML** позволяет задать до 16 пар поиска и замены. Это обычные настройки маршрута: в AmberGate нет специальных веток или пресетов под конкретные приложения. В замене `{prefix}` означает текущий путь маршрута. Например, для встроенных в HTML настроек приложения:

| Найти | Заменить на |
|---|---|
| `"basePath":""` | `"basePath":"{prefix}"` |

Каждое поле — одна строка до 1024 символов, без `$`. Поиск не учитывает регистр, как `sub_filter` в Nginx. Изменения сохраняются локально в черновике, вступают в силу после применения и попадают в историю конфигурации.

Режим включается отдельно для маршрута с непустым префиксом и его удалением из запросов. Обрабатывается HTML; JS-файлы, JSON API и бинарные ответы не переписываются. Сжатие ответа upstream отключается для обработки HTML. Адреса, создаваемые JavaScript, CSS, `srcset`, CSP, OAuth и встроенные настройки приложения могут потребовать дополнительных замен в маршруте либо отдельного домена: автоматически определить смысл всех строк любого приложения невозможно. Авторизация, cookies запросов и WebSocket работают по обычным правилам gateway. Для подписанных API вроде S3 этот режим включать не следует.

HTTPS на внешнем TLS-прокси совместим с этим режимом: AmberGate обрабатывает HTTP-ответ приложения до его шифрования внешним прокси.
